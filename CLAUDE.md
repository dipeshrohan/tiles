# CLAUDE.md

Guidance for Claude Code working in this repository.

## What this is
Tiles is a browser app for industrial R&D and shopfloor teams: a factory ontology with Git-style change history, physics-based virtual sensors, a correlation finder, a design studio and a copilot. It is currently front-end only, with seeded synthetic data. The roadmap (docs/ROADMAP.md) adds a Python backend and real plant data.

## Commands
- `npm run build`: Vite build of `js/app.ts` into `js/tiles.bundle.js` (one classic script, minified, so `index.html` works from `file://`; read the sources in `js/`, not the bundle). **Required after editing anything in `js/`, `docs/guides/user.md` or `CHANGELOG.md`** (it also writes `js/help-data.js`, U4.04, and each catalogue's `js/messages-<code>.js`, U6.01); `npm test` fails if the bundle or the help is stale. `npm run dev` rebuilds on save.
- `npm run lint`: ESLint and Prettier check. `npm run format` fixes formatting and rebuilds.
- `npm run typecheck`: strict TypeScript (`tsc`, includes `noUncheckedIndexedAccess`).
- `npm test`: Vitest unit tests, including the bundle freshness check.
- `npm run test:visual`: visual regression tests (U1.08, `e2e/visual/`): every page (full length, each in a fresh tab; a test fails when a page in `js/views/` is missing from its list) in light, dark and on a phone, plus empty, error and dialog states, compared with the PNG baselines in `e2e/visual/baselines/`, in the Playwright container (Docker) so fonts match CI's Visual regression job; differences land in `e2e/visual/output/` (a CI artefact). After a deliberate visual change run `npm run test:visual -- --update` and say why in the PR.
- `npm run test:perf`: the performance budget (U3.07, `e2e/perf/perf.test.js`, CI's Performance budget job): long tasks (≤ 50 ms) and Interaction to Next Paint (< 200 ms) on the ontology with 2,069 nodes, 5,000 signals and the Data explorer with 4 signals over 30 days, Lighthouse ≥ 90 on Home, and the gzipped bundle and stylesheet sizes; a deliberately slow handler must fail it.
- `npm run test:e2e`: Playwright smoke tests. In Claude Code cloud sessions Chromium is preinstalled; do not run `playwright install` there.
- `npm start`: serve on http://localhost:5173.
- `docker compose up --build --wait`: full stack (TimescaleDB, Redis, API on 8000, web on 5173); `docker compose down -v` resets it. In cloud sessions Docker Hub may rate-limit and the TLS proxy breaks in-container `pip`; see CONTRIBUTING for the workaround.
- Backend (`api/`, Python 3.12+, managed with `uv`): `uv sync`, then `uv run tiles-api` (port 8000), `uv run pytest -W error`, `uv run mypy` (strict), `uv run ruff check .` and `uv run ruff format .`. Run them from `api/`. Database tests need `TILES_TEST_DATABASE_URL` (they are skipped locally without it and fail in CI). Schema changes go in a new migration: `uv run tiles-migrate revision "…"`.
- Edge agent (`edge/`, Python 3.12+, `uv`): `uv sync --all-extras`, then the same `uv run pytest -W error`, `uv run mypy`, `uv run ruff check .` and `uv run ruff format .`, run from `edge/`. The SQL connector tests start PostgreSQL and SQL Server in Docker (`tests/sql_servers.py`); without Docker they are skipped, except with `TILES_EDGE_TEST_DOCKER=1` (set in CI), where they must run. The SQL Server driver needs `libltdl7 libkrb5-3 libgssapi-krb5-2`.

## Layout
- `js/lib/*.ts`: pure logic in strict TypeScript (ontology, physics, analysis, design models, copilot routing, stats, charts). Shared types in `js/lib/types.ts`. Import with the `.ts` extension. Unit-tested in `test/`.
- `js/lib/canvas.ts`: the ontology canvas at scale (T2.14): folding by hierarchy (`contains`, `controlledBy`, `emits`), the column layout that wraps tall columns, search, and the view box for zoom and pan; the Ontology page draws it and handles the wheel, drag and double-click. The builder (U5.05) adds, from the same file, `stepFrom` (arrow keys), `inBox` (a Shift-dragged box), `focusView`, `minimapPath` and `likelyRel` (the relationship a drag from a node's handle onto another suggests); undo and redo of staged ops are steps kept by the page, sent as `store.unstage` (`POST …/ontology/staged/undo` with `count` and `of`, refused when the staged ops changed elsewhere). `test/fixtures/large-plant.js` is a 2,069-node plant for tests.
- `js/lib/csv.ts` and `js/lib/importer.ts`: the CSV parser and the bulk-import logic (column mapping, time formats and zones via `Intl`, readings in batches) behind the Import data page (`js/views/imports.ts`), which reads the file in the browser and sends it to the API. The Signals page (`js/views/signals.ts`) is the catalogue's browser side; the Data explorer (`js/views/explorer.ts`) plots signals with `timeChart` from `js/lib/svg.ts`, from `api_series.py` (T2.10: raw readings, or `time_bucket` averages with min and max). Compare mode (U5.09, `js/lib/compare.ts`): two ranges of one signal shift-aligned from their starts (`otherRange`, `align` on equal buckets, `summarise` over the buckets both have), or two signals over one range, drawn with `lineChart` with the difference below; in the address as `compare=ranges&cs=&against=&cstart=` or `compare=signals&ca=&cb=`. The Warnings page (`js/views/warnings.ts`, logic in `js/lib/warnings.ts`) is the warnings inbox (T3.08): filters, the signal around a warning (`timeChart` with threshold and baseline `levels` and the warning as a shaded `span`), its payload and activity, and the workflow steps. The Shopfloor page (`js/views/shopfloor.ts`, logic in `js/lib/shopfloor.ts`, T5.16) is the same warnings for a tablet on the line: placed on their machines through the ontology (Signal ← emits PLC ← controlledBy Machine), worst first, with 64 px buttons, a machine board, a 30 s refresh and a full view (`body.floor-full`). The Plant page (`js/views/plant.ts`, logic in `js/lib/plant.ts`, T5.17) is the site → workcenter → line → machine navigator over the same hierarchy (`#/plant/<node id>`), with warnings rolled up and a sheet per machine. A place's Coverage card (T7.01, `coverage.py`, `GET /sites/{id}/coverage?place=`, `Ctx`) lists each machine under it with its linked signals, detectors, model bindings and event streams (matched by the machine node's `asset` property, else its label) and what is missing (`signal_nodes`, `linked_tags`, `detector`, `event_stream`). Both share the open warnings and the catalogue's linked signals through `js/views/floor-data.ts`, and the cached edge index in `js/lib/graph-index.ts`. The Shopfloor's field round (U5.08, `docs/pilot/field-round.md`): High contrast (`body.floor-contrast`, kept as `floor-contrast`; also `prefers-contrast: more`), offline said under the headline (`freshness`) with its buttons waiting and a refresh on `online`, and a screen wake lock while the page is shown; every control on `.floor` is at least 64 px (the e2e measures it).
- `js/views/*.ts`: one module per page; each default-exports a `View` (`{ id, title, icon, render(ctx), bind(root, ctx), crumbs?(ctx) }`, see `js/views/types.ts`). A page starts with `pageHead()`; `crumbs` gives the record or place the URL points to (`#12`, `Line 2 › DC-01`), shown after Home › the page in the top bar's breadcrumbs. Per-page UI state goes through a typed `uiState(ctx)` helper with defaults; it is kept in the tab's session storage across a reload (U3.05, `js/lib/url-state.ts`). What a link should share (filters, search, the record open, a range) goes in the page's address: a `query: { read(params, ctx), write(ctx) }` on the View (Warnings, Signals, the Data explorer); the app reads a query that came from outside before drawing, and writes the page's after (`ctx.address()` for a change that doesn't draw the page). Back and forward put the scroll back. A list with records (Warnings, Change reviews, Insights, Documents) draws `split(list, record, { open, back, label })` from `js/lib/split.ts` (U3.08): side by side from 960 px, one at a time below it (the record, with a way back), and `listKeys(root, rows, isOpen)` for j and k; the address names the record (`#/reviews/<n>`, `#/insights/<n>`, `#/documents/<n>`, `?warning=`), and a record opened from the list keeps the focus on its row.
- `js/app.ts`: state, router, persistence (localStorage via `js/lib/store.ts`). The menu (U3.06, `js/lib/nav.ts`, drawn by `renderNav`): groups that fold, pins and the last five pages, counts (open warnings and reviews waiting for me, read quietly through `api.menu` at most once a minute), and an icon rail for wide screens, each person's choices kept per user (`nav:<user>`); on a phone, a scrim, a focus trap and swipe to close.
- `js/lib/api.ts`: typed client for the Tiles API (`createApiClient`, `ApiError`) and the data-source flag (`local` or `api`, set in Settings or with `?api=<url>`). Views reach it as `ctx.api`, which is null in local mode; failed calls already show a toast.
- `js/lib/ontology-store.ts`: the ontology page changes `state.repo` only through `ctx.ontology.act(store => …)`, where the store is local (this browser) or remote (the API, reloaded after each change). Browser tests use the in-memory fake API in `e2e/fake-api.js` (which can also play the sign-in provider).
- `js/lib/oidc.ts`: browser sign-in (Authorization Code + PKCE, tokens in sessionStorage, refreshed before expiry); `ctx.auth` exposes it.
- `vite.config.js`: builds the IIFE bundle and configures Vitest. `scripts/check-bundle.js` compares a fresh build with the committed bundle.
- Icons: `icon(name, { size, label })` from `js/lib/icons.ts`, Lucide's line icons (the set shadcn/ui uses) in `js/lib/icon-data.ts`, generated from the pinned `lucide-static` dev dependency by `npm run icons` (add the name to `scripts/icons.js`; `test/icons.test.js` checks the file is current and that each page's `View.icon` is its own). Components follow shadcn/ui's look in plain CSS: `.btn` (outline) with `.primary`, `.secondary`, `.ghost`, `.danger`, `.destructive`, and `.sm`, `.lg`, `.icon`.
- Page states: `emptyState({ illustration, title, body | bodyHtml, action, compact, alert })`, `skeleton.table(rows, cols)`/`.list()`/`.card()`/`.chart()`/`.text()` (U2.04: the shape of what loads, after 300 ms, `aria-busy`; `loadingState(label)` is `skeleton.text`), `button(label, { busy })` or `setBusy(el, busy)` for a button at work, and `needsApi(bodyHtml)` from `js/lib/ui.ts`; illustrations (`js/lib/illustrations.ts`) are line art coloured by theme classes, never fixed colours. The command palette (`js/lib/palette.ts`, Ctrl/⌘ K or /, U4.02) lists the menu's pages, the actions in `app.ts` (one for each of the six key tasks; add an action there) and the other sites; in API mode it searches the site as you type (`api.search`, results made items by `js/lib/site-search.ts`, each opening its record by address: `#/ontology?node=`, `#/warnings?show=all&warning=`…), keeps the last picks, records among them, and offers to ask the copilot what was typed (`prefill` in `js/views/chat.ts`). Keyboard shortcuts (U4.03, `js/lib/shortcuts.ts`): `g` then a letter (`GO_KEYS`), `?` lists them all (with the switch that turns single keys off, WCAG 2.1.4), and a page's own key is the `aria-keyshortcuts` of its button or field, given with `keyAttrs(key)`/`keyAttr(key)` (nothing while they are off): `installShortcuts` clicks or focuses the first shown, enabled one in `#view` (`/` a page's search, else the palette), and the tooltip shows the key; a new key goes in `PAGE_KEYS` too. Keyed handlers check `forShortcut(e)` (not while typing, with a modifier, in a dialog, or turned off).
- Help (U4.04): `scripts/help.js` cuts `docs/guides/user.md` at its headings into `js/help-data.js` (HTML made at build time by `helpPlugin` in `vite.config.js`, again under `npm run dev` when the guide changes; the build fails when a page in `js/views/` has no section in its `PAGE_HELP`, so a new page adds one, and a section to the guide when it needs it; `test/help.test.js` checks the file is current and the links land), a classic script that `js/lib/help.ts`'s `loadHelp()` adds the first time help is wanted (from `file://` too; the bundle stays under its budget). The top bar's help button opens the page's section in a side sheet (`sheet()` in `js/lib/overlay.ts`), with a link to the Help page (`js/views/help.ts`, `#/help/<section>`: one section of the guide at a time, `chapter()`, with its contents and Previous and Next); the palette lists the guide's headings once loaded, after everything else (`PaletteItem.late`, the best five).
- First run (U4.06, `js/lib/welcome.ts`, `firstRun`/`showWelcome` in `app.ts`): once the person is known (at once locally, when the API answers in API mode), the app opens at their start page (`NavPrefs.start`, only while nothing has been navigated since it loaded) and, the first time (`welcome:<nav owner>` in localStorage), a welcome (`panelDialog` in `overlay.ts`) asks their role: `applyRole` pins its pages, folds its groups and sets the start page; then it offers the site wizard (an admin of a site with no plant model), the start page and its help. Automated browsers (`navigator.webdriver`: the e2e tests, Lighthouse) aren't greeted; tests open it from Help (`[data-show-welcome]`, the `tiles:welcome` event) or the palette.
- Preferences (U6.06, `js/views/preferences.ts`, logic in `js/lib/preferences.ts`, `api_preferences.py`, migration 0038): theme, table density (`setTableDensity` in `data-table.ts`: the default, and on a change every table's), motion (`data-motion`), language, number format (`chooseFormat` in `format.ts`, over the language's), the site's clock or the device's, single-key shortcuts and the start page (`NavPrefs.start`). `currentPreferences`/`setPreferences`/`applyPreferences` in `app.ts` (`ctx.preferences`): applied at once, kept under `preferences` in localStorage (the language, shortcuts and start page where their modules keep them), and with the API with the person on every site (`GET/PUT /sites/{id}/me/preferences`, `Ctx`, audited; `user_preferences` has no site, so it is in `NO_SITE`), read in `firstRun` before the start page opens. The theme button, the `?` list's switch and the welcome change them too.
- What's new (U4.08): `scripts/help.js` also makes the changelog's top section (`whatsNew`: version, date, HTML; an entry whose task is in `TASK_PAGES` links to its page) into `js/help-data.js`, so a CHANGELOG edit needs a build like a guide edit (`test/help.test.js` catches a stale file). `js/lib/whats-new.ts` and `openWhatsNew` in `app.ts`: a dot on the help button (`has-news`, named in its label) when `whats-new-seen` holds an earlier version (a first visit only notes it; someone with other Tiles data kept here gets the dot); the sheet opens from the help sheet, the Help page and the palette, and marks the version seen.
- Guided tours (U4.07): tours are data in `js/lib/tours.ts` (steps on a page, each naming a `data-tour="…"` attribute a view draws, with `reveal` to open a record first and `missing` when it isn't there); `js/lib/tour.ts` runs one (`runTour`: a spotlight that lets clicks through, a non-modal popover that takes the focus, Next, Back, Leave, Escape; `placePopover`). Started from Help, the palette or the welcome through the `tiles:tour` event (`startTour` in `app.ts`); tours of the API's data need it (`canRun`). `test/tours.test.js` checks every target is still drawn by a page, and the e2e tests walk all four (`walkTour`). Renaming a `data-tour` means changing its tour.
- Glossary (U4.05): `docs/ui/glossary.md` (a `##` group, a `###` term, one paragraph of plain words) is made into `js/lib/glossary-data.ts` by `npm run glossary` (`scripts/glossary.js`; `test/glossary.test.js` checks it is current). `term(key, text?)` from `js/lib/ui.ts` shows a term where it first appears on a page: its words dotted, the definition in a tooltip on hover, focus or a tap (`js/lib/tooltip.ts`); `pageHead({ leadHtml })` takes terms in a lead. The analytics pages (Correlation finder, the wear check, Warning performance, a warning's chart, Factory physics, Process & quality) explain their statistical terms this way; a new term goes in the glossary first. The Glossary page is `js/views/glossary.ts` (`#/glossary/<term>`, under Help); the palette finds its terms after the rest.
- Undo instead of confirm (U2.03, `js/lib/undo.ts`): what can come back is removed at once with an Undo toast for 8 s. `removeLater({ toast, message, removal, hide, restore, send, sent })` sends the change only when the toast goes (conversations, batch tables; views filter their lists with `isRemoving`; removals still waiting when the page is left are saved on `pagehide` and sent by the next load, `takeSaved` in `app.ts`, unless the page comes back from the back/forward cache); `removeNow({ toast, message, send, undo, restored, restoredMessage })` archives at once and Undo calls the API's restore (documents and apps: `POST …/documents/{n}/restore`, `…/apps/{n}/restore`). A toast's `onDone` runs when it goes without its action pressed.
- UX analytics (U1.09, `js/lib/analytics.ts`, `api_ux.py`, migration 0033): off until an organisation admin turns it on (`orgs.ux_analytics`, `PUT /org/ux-analytics`, audited for the organisation); then `ux(kind, name)` from anywhere records a page viewed, a task done (`warning.acknowledge`, `signal.plotted`…), the command palette, help or an error shown, batched by the tracker in `app.ts` to `POST /sites/{id}/ux-events` (`silent` requests: no toast, no banner). Names are plain lower-case words from the app, never user data (the API and the tracker both refuse anything else); the tab's random session is stored hashed; a hypertable whose retention policy drops them after 90 days; at most 5,000 events an hour per site and 600 per session; not audited (like a person's copilot conversations, they change nothing on the site); what a page leaves unsent is kept in localStorage for the next load; site admins see counts in Settings (`js/views/ux-analytics.ts`). The admin guide lists the vocabulary: add a new name there.
- Charts v2 (U5.03): `timeChart` and `lineChart` (`js/lib/svg.ts`) register their readings with `registerChart` (`js/lib/chart-data.ts`: x and y in the chart's units, each reading's time and value as read out, and the CSV), under an id made from the data, and come in a `.chart-box` with their tools (a legend of `data-part`s to show and hide, PNG, CSV) above a focusable `svg[data-chart]`. `installCharts` (`js/lib/charts.ts`, once in `app.ts`) draws the crosshair on pointing, a tap and the arrow keys (read out by `#announcer`) and handles the tools; a page's own pointer handling on a chart (the explorer's drag to zoom) starts only on the `svg`, so the tools stay buttons.
- Print (U6.05): the `@media print` block at the end of `css/styles.css` prints a page as a document (no menu, top bar, `.btn`s or search boxes; the record alone when a split has one open; tables and charts within the paper's width; rows, comments and charts kept whole; light whatever the theme; lines dashed by `data-part` `s1`…, shaded spans hatched with `#print-hatch` from index.html). Hide a record's action form or tools on paper with `no-print`, and mark a link that reads as its address `print-plain`. Links print their address after them (Tiles' own after `--print-base`, the app's address set by `installPrint` in `js/lib/print.ts`, never from `file://`); folded details print open (`::details-content`, or `installPrint` where that is missing). A list prints the rows on screen. `e2e/print.test.js` prints a warning, an insight, a review, the run history and a machine's page on A4 and Letter.
- Tables v2 (U5.02, `js/lib/data-table.ts`): `dataTable(o)` in a page's HTML and `bindTable(root, o)` in its bind (or after it fills a box), with `columns` (`cell` markup; `value` makes it sortable and is its CSV value; `fixed`, `srOnly` for actions), `rows` (null: a skeleton), `key`, `empty`, `status`, `after` (a row's detail or form), `select` (bulk actions), `pageSize` (pages) or virtual rows past `VIRTUAL_AFTER` (200), and `csv`; sort, hidden columns, widths and density are kept per table id (`table:<id>`). Used by Signals, Settings' edge agents and audit log, and the record lists (Warnings, Change reviews, Insights, Documents: the row carries `data-<record>` and `.sel`, its first cell a `.row-open` link or button that `rowTarget` finds; `rowClicks(root, list, rows)` opens a record from anywhere in its row). Rows a table draws again (sorting, scrolling) lose listeners added to them: handle their clicks on the list (delegation), or re-wire them in `drawn`.
- Home by role (U5.01, `js/views/home.ts`, logic in `js/lib/home-cards.ts`, data in `js/views/home-data.ts`, `api_home.py`, migration 0035): in local mode the demo's hero; with the API, cards (`CARDS`, each with the `needs` it fetches) set by role (`ROLE_CARDS`; `homeRole` from `ctx.workRole`, the welcome's choice, or the site role), added, moved and removed with Customise and kept per person and site (`GET/PUT/DELETE /sites/{id}/me/home`, `Ctx`, audited). A new card: add it to `CARDS`, its body to `cardBody` and its link to `CARD_LINKS`.
- Filter bar and saved views (U5.06, `js/lib/filter-bar.ts`, logic in `js/lib/saved-views.ts`, `api_views.py`, migration 0036): `filterBar(ctx, o)`/`bindFilterBar(root, ctx, o)` with `{ page, filters(), count(), apply(f) }` under a list's own filters (Warnings, Signals, Documents); `FILTERS` names each page's filters (its address's params, U3.05), a saved view keeps those set (`viewQuery`) and the table's sort, hidden columns and density (`tablePrefs`/`setTablePrefs` in `data-table.ts`), and opens by an address that writes every filter out (`viewHref`). Views are a person's (`Ctx`) until shared (engineer or above), changed by their owner, deleted by them or a site admin (shared), audited; `viewsFor(ctx)` keeps them (per API, site and user, read at most once a minute) for the bar and the menu's **Saved views** (`tiles:views` redraws both). A new page with filters: add it to `FILTERS`, the API's `Page` and the migration's check.
- Notification centre (U5.07, `api_inbox.py`, migration 0037, logic in `js/lib/inbox.ts`, the bell in `app.ts`): the inbox is worked out when read (`GET /sites/{id}/inbox`: warnings assigned to you by someone else and not resolved, change requests and insights you may review, your imports left unfinished for an hour), so an item goes once it no longer waits; `inbox_reads` keeps what each person read by the item's key, which names its version (a warning assigned again is new); `POST …/inbox/read` with `keys` (none: all), `Ctx`, audited. The bell (hidden in local mode) asks at most once a minute (and on coming back to the tab), announces new unread items in `#announcer`, and its sheet links each item. A new kind: a branch of `ITEMS` in `api_inbox.py`, the fake API's and `KIND_ICON`.
- In-app feedback (U4.09, `api_feedback.py`, migration 0034; browser `js/lib/feedback.ts`, the dialog `openFeedback` in `app.ts`, the admins' card `js/views/feedback-admin.ts`): **Send feedback** in the help sheet's foot, on the Help page (API mode) and in the palette (`do:feedback`, `tiles:feedback`). Any member sends a mood, words, the page's id, version and user agent; a name only when ticked (`user_id` null otherwise, audited as "Anonymous"); a screenshot only when ticked, made by `capturePage` (`js/lib/screenshot.ts`: the page copied with its stylesheet's rules into an SVG `foreignObject`, drawn to a JPEG; none from `file://`, whose stylesheets can't be read) and shown before it is sent. Admins list, view and delete (`removeLater`, kind `feedback`).
- Overlays: ask with `await confirmDialog({ title, body, confirm, tone: 'danger', typeToConfirm })` from `js/lib/overlay.ts` (native `confirm`/`alert`/`prompt` fail lint); `ctx.toast(message, { type, description, action })` (`js/lib/toaster.ts`); `data-tooltip="…"` on any element gives it a tooltip (`js/lib/tooltip.ts`). A dialog doesn't block the page: re-check what it was about after the `await`.
- Components in `js/lib/ui.ts` (U1.04), after shadcn/ui: `button`, `iconButton`, `linkButton`, `badge`, `chip`, `card`, `pageHead`, `field` (label, hint), `input`, `select`/`options`, `table`, `kv`, `tabs` (a toggle group of filters), `emptyState`, `errorState`, `loadingState`, `needsApi`; the `attrs` option can't set a component's `class` or `type`. The style guide (`#/styleguide`, `js/views/styleguide.ts`, U1.07) shows them with their code from `js/lib/styleguide.ts`, which lists every `:root` token (`test/styleguide.test.js` keeps it in step: a new token goes there too). They escape every text argument (options named `*Html` take built markup); use them in views rather than writing the markup.
- Rendering (U3.03): a new page replaces `#view`; the same page drawn again is patched in place by `js/lib/morph.ts` (`morph`, matched by `id` or `data-key`, then by position, tag, name and first class), so focus, the caret, scroll, opened `<details>`, selections and typed values survive (a typed field follows the page only when its HTML changes or its form was sent, `noteSent`). A large drawing marked `data-morph="replace"` (the ontology canvas) takes its new content whole, the focus kept by key, and an element marked `data-morph="if-changed"` (a select of 2,000 nodes) is left alone when drawn the same (U3.07). `bind` runs after every render: every listener a view adds passes `{ signal: bound() }` from `js/lib/dom.ts` (the last binding's are dropped by `rebind`; `test/view-listeners.test.js` checks), and per-element state belongs in a `WeakMap`/`WeakSet`, not a `data-` flag (the morph removes attributes the HTML doesn't have). Give list rows a `data-key` when rows can be added or removed. `e2e/morph.test.js` loads morph.ts on its own in Chromium.
- DOM helpers in `js/lib/dom.ts`: `need()` (querySelector that throws if missing), `field()` (form values), `onAll()` and `onSubmit()` (typed event wiring). Prefer them over raw querySelector in views. `onSubmit` checks the form first (U2.07, `js/lib/forms.ts`): the browser's constraints (`required`, `pattern` with a `title`, `min`, `max`) shown under each field with `aria-invalid`, a summary at the top linking to them, and each field checked again as it is left; a view's own checks return `FieldError`s for `showErrors(form, errors)`. The API's 422 field errors (`ApiError.fields`) land on the form sent last, kept when it is drawn again; `data-api="…"` names a field the API calls differently. A handler that returns its request's promise holds the form while it runs (U2.08: the button busy, a second sending ignored); `onAction(root, sel, handler)` does the same for a button. ## Rules
- Add or update tests with every behaviour change; never skip or disable a test.
- A site's data is under row security (T5.04, migration 0024), closed when no site is named: a new table with a `site_id` needs a forced `site_rows` policy in its migration, and a table that belongs to a site through a parent needs one through the parent (`tests/test_row_security.py` fails otherwise). Requests are scoped by `SiteContext`; a pooled connection used outside one must scope itself (`store.scope_to_site`); jobs connect with `store.connect_job` (every site, working as `tiles_app`; threat model G-D1); widen with `store.all_sites` only for what spans sites. The API reads readings from the `site_samples` view and stores them with `tiles_store_samples`, never the `samples` table.
- Credentials stored in the database are sealed with a data key (`sealed.py`, T5.06; `sealed.seal`/`unseal` with a context naming the row) and never shown again; settings that hold secrets are `SecretStr`. See `docs/runbooks/secrets-and-encryption.md`.
- Keep the browser app free of runtime dependencies.
- Relative links in Markdown must resolve, headings included (`test/doc-links.test.js`, GitHub's anchors). `docs/security/partner-review.md` (T3.15) is the cover a partner's IT/OT team gets with the threat model: connections, the data end to end, a questionnaire quick reference and the open items; keep it true when a connection or a data flow changes. `docs/security/pentest-brief.md` is the external penetration test's scope, environment, accounts and rules (T6.07). `docs/security/compliance-readiness.md` (T6.08) maps controls to SOC 2 and ISO 27001 with their evidence in this repository: update it when that evidence moves.
- Words on pages follow `docs/ui/writing.md` (U2.09): sentence case, buttons as verbs, errors as what happened, why and what to do, units and dates as it says, its terms; `test/copy.test.js` checks the mechanical rules. A page that needs the API and can't reach it shows `apiUnreachable(error)` (Try again reconnects). A failed request's toast comes from `describeApiError` (`js/lib/errors.ts`, U2.06: by status, with its way out); offline, the client refuses changes with the code `OFFLINE_WRITE` (`ApiError.code`) and `#offline` shows a banner; `errorState({ details })` adds Copy details (`errorDetails`, with `VERSION` from `js/lib/version.ts`, which `scripts/version.js` keeps).
- Words come from the message catalogue (U6.01): `t(key, params)`/`tHtml(key, params)` from `js/lib/i18n.ts` over `js/i18n/en.json` (keys typed by `MessageKey`; the messages aren't in the bundle: `scripts/messages.js` makes each catalogue a classic script, `js/messages-<code>.js`, that adds itself to `window.TILES_MESSAGES`, English loaded by index.html before the bundle, `test/setup.js` and `e2e/fake-api.js` loading it for Node; ICU-style values, `plural` by `Intl.PluralRules` with `#` written as the language writes numbers, and `select`), never text written into `js/app.ts`, `js/views` or `js/lib` (`scripts/check-i18n.js` in `npm run lint`: hard-coded text, keys missing from or unused by a locale; `// i18n-ok` marks a line whose text isn't words; content files in its `CONTENT`), never `t()` while a module loads (keep keys or getters), whole sentences rather than joined pieces, real plurals rather than "(s)"; a `t()` whose words land in markup goes through `esc()` (`scripts/i18n-escape.js`, in lint, finds any that don't; `--fix` wraps them), and `tHtml` takes only built markup or escaped text as values. Text stored in shared data (a revert's commit message) stays in one language, as the API writes it. `index.html`'s fixed words carry `data-i18n*` keys. The API raises `errors.Problem(status, code, English, **params)` (`errors.py`), never a bare `HTTPException`, and a stream's `error` event says an `errors.Refusal(code, English, **params)` (the copilot's): every error answers `{detail, code, params}`, and the catalogue's `api.<code>` says it (`tests/test_errors.py` checks both sides); the browser shows `api.<code>` (a field's `api.field.<Pydantic type>`) when it has it (`errorMessage` in `api.ts`). See `docs/ui/writing.md`.
- Languages (U6.03, `js/lib/language.ts`): English and German (`js/i18n/de.json`; `LANGUAGES`, named in their own language), and the pseudo-locale `en-XA` made from English (`pseudo`: accented, 40% longer, bracketed; the visual tests run every page in it, failing on sideways overflow). `chosenLanguage` (`?lang=`, kept in `language`; then the browser's), `useLanguage` (adds `js/messages-<code>.js` beside the bundle, then `setLocale` and `<html lang>`); app.ts draws only once the language is loaded; Your preferences chooses another (U6.06). A translation has English's keys and each message English's `{values}`, plurals and selects (`shape` in `scripts/check-i18n.js`); a new message needs its German too (marked for review in the PR).
- Numbers, dates and times by language and site (U6.02): `js/lib/format.ts` (imports nothing; `i18n.ts`'s `setLocale` sets its language, en as en-GB): `number`/`upTo`/`significant`/`percent`, `duration` (writing.md's units), `date`/`dateTime` (the zone named)/`time`/`month`/`dayMonth`/`year`, `relative` (`timeAgo`), `textOrder` (a collator: get it once per sort), and for working out times on the site's clock `zonedParts`/`zonedTime`/`zoneOffset` (chart ticks, shift starts) and `inputValue`/`fromInput` (datetime-local inputs); times in the site's zone (`Site.timezone` from `GET /sites`, `setTimeZone` when the site opens; this browser's without the API). `dom.ts`'s `fmt` is `number`. Never a locale written into a `toLocale*String`, an `Intl` constructor or `localeCompare`, nor the browser's (`toLocaleString()`), nor a percentage made with `toFixed` (`scripts/check-format.js`, in lint); a plural's `#` follows the page's number format; a locale for parsing goes in a const. Formatters are cached per language, zone and options.
- Escape any interpolated text with `esc()` when building HTML strings.
- Motion follows `docs/ui/motion.md` (U3.01): `--dur-fast`/`--dur`/`--dur-slow` (and `--dur-spin`/`--dur-shimmer` for progress), ease-out in and ease-in out, only opacity and transform, one thing moving at a time, nothing looping but progress, all stopped by reduced motion (the system's, or `data-motion="reduce"`); a scroll from script uses `scrollBehavior()` from `js/lib/dom.ts`; moving to another page is a view transition (U3.02, `navigate` in `js/app.ts`: a cross-fade with the page head held, a record grows from the link clicked; none when `lessMotion()`), and the new page's `h1[tabindex="-1"]` (from `pageHead`; a page drawing its own `h1` adds it) takes the focus; drawn again in place, keyed rows fade in and out, `.kpi .value`/`[data-tick]` numbers tick and selected highlights (`::before`) glide (U3.04, `js/lib/micro.ts`, the morph's `enter`/`leave` hooks); `test/motion.test.js` checks the stylesheet.
- Styles use the design tokens in `css/styles.css`'s `:root` (U1.02): `--space-*`, `--text-*`, `--radius-*`, `--shadow-*`, `--z-*`, `--dur*`/`--ease-*`, and colours as `light-dark()` pairs; `test/css-tokens.test.js` fails on raw px for spacing, type or radius. No `style` attributes in the HTML the app builds (U1.03): use a component class or the utilities at the end of `css/styles.css` (`.gap-N`, `.mt-N`/`.mb-N`, `.grow`, `.wrap`, `.justify-between`, `.text-bad`…, `N` a `--space-N` step); `scripts/check-inline-styles.js` (in `npm run lint`) allows only computed values.
- Pages must pass `e2e/a11y.test.js` (axe, WCAG 2.1 AA, light and dark; T5.18; and U6.04's: no sideways scroll at 320 px or 640 px, a visible focus on every control reached by Tab, also in forced colours, what is chosen outlined in forced colours, controls of `--target-min` (24 px) or in a sentence or spaced apart; report and screen-reader flows in `docs/ui/accessibility.md`): real buttons and links, labelled fields and table headers (`sr-only` for an action column), charts from `js/lib/svg.ts` (each gets a name and a summary of its numbers; pass a `title`), text colours that meet 4.5:1 (`--warn-ink` for text, `--warn` only for lines), underlined links in running text. See CONTRIBUTING.
- Task IDs (T1.01 …) map to GitHub issues; reference the issue in PRs.
