## Warnings

[backtests/summary.json](../../data/sample-plants/die-casting/backtests/summary.json) and the

[die-cooling.md](../../data/sample-plants/die-casting/backtests/die-cooling.md)). Running
`uv run tiles-sample-plant backtest die-casting` from `api/` on 2026-11-18 printed "beats its
target" for each and left the committed files unchanged.

## Copilot

**The evaluation set with the oracle model.** The 18 cases of
`api/src/tiles_api/evaluation/cases.json` (the root-cause case added in T10.03), asked through
`evaluation.run` with `tests/test_evaluation.py`'s `Oracle` on a database on 2026-11-18, scored by
`evaluation.report`. `test_every_case_is_answerable_from_the_plant` asserts the same scores. The
oracle calls each case's planned tools and states its facts, so this proves every case can be
answered and grounded; it doesn't score a model.

| Measure | Oracle | Claude | Gate |
| --- | --: | --: | --- |
| Accuracy | 100% (18/18) | ‹needs the copilot's key› | at least 85% |
| Unsupported claims | 0 | ‹needs the copilot's key› | at most 0 |
| Tool choice | 100% | ‹needs the copilot's key› | at least 90% |

`TILES_ANTHROPIC_API_KEY` isn't set where this report was made, so `tiles-evaluate` couldn't ask
Claude. CI's Copilot evaluation job runs it when the repository has the key and model; its report is
a CI artefact, not a file in the repository.

**The sample plants' question sets.** Each plant's `copilot/questions.csv`, counted with
`evaluation.read_csv`, answered by the oracle from the loaded plant through the grounding check by
`api/tests/test_sample_<plant>.py`'s `test_every_question_is_answered_from_the_loaded_plant`, which
asserts accuracy 100% and no unsupported claims. All four passed on 2026-11-18
(`uv run pytest -W error tests/test_sample_*.py` with `TILES_TEST_DATABASE_URL`).
